## Done when
### A. Format v2 + migration (`src/shared/validate.ts`)
- `defaultMuseum()` returns v2 with `settings.wallFinish = { color: '#ffffff', tileSize: 1 }`.
- `parseMuseum` accepts v2 and validates the new fields: `kind` ∈ image|audio|texture; width/height
  required for image AND texture; title/artist/description optional strings; `WallFinish.color`
  matches `/^#[0-9a-fA-F]{6}$/`; `tileSize` finite > 0; `textureId` (settings or wall) references a
  media item with kind `'texture'`; `Work.mediaId` must still be kind `'image'` (a texture can't be hung).
- `parseMuseum` also accepts **v1** and returns a migrated v2 museum: for each media item, take
  title/artist/description from the first work (in array order) that uses it and has a non-empty value
  for that field; drop those fields from works; add default `wallFinish`; set version 2. v1 files that
  were invalid under v1 rules stay invalid. Any other version → error as today.
- Tests: v2 happy path; each new error class; v1→v2 migration incl. two works sharing one media with
  different titles (first wins), a work with an empty title not overriding a later non-empty one,
  and a test that parses a **copy** of the user's `public/museum/museum.json` (read it in the test,
  don't write it) and asserts ok + version 2.

### B. Viewer (`src/viewer/**`)
- Labels read title/artist/description from the work's media item; no label if all are empty.
- Walls use their finish (wall override, else settings default): colour, or texture × colour, tiled
  so one tile = `tileSize` metres on every face (long faces, ends, top) — no stretching. Texture
  images are loaded once per media item (missing texture → plain colour + console warning, like
  missing images). Textures capped at 1024 px, sRGB, mipmaps, repeat wrapping. Keep the "walls drawn
  T longer so corners have no notch" behaviour; UVs must account for it.
- Keep draw calls reasonable on Quest: walls that share an identical finish may share one material.

### C. Editor (`src/editor/**`)
- Media library has three sections: **Paintings** (kind image), **Textures**, **Audio**. Uploading
  into Paintings or Textures is explicit (separate drop zones / pickers per section, or a section
  chooser). Textures resize to max 1024 px (paintings stay 2048). New paintings get title = filename
  without extension, artist/description empty.
- Painting metadata (title, artist, description) is edited on the media item: from the library
  (select a painting → inspector shows its fields, preview, "hung N×") and from a selected work's
  inspector (same fields, editing the media item; show "shared by N works" when N > 1).
- **Hang random**: a control in the hang tool / library ("Random painting"). Each click on a wall
  face hangs a painting chosen uniformly from paintings not referenced by any work; if all are hung,
  uniformly from all paintings; if there are none, show a notice and do nothing. A selected work's
  inspector has **"Pick another"** applying the same rule (excluding the current painting when
  another choice exists). Put the choice in a pure function `pickRandomPainting(museum, rng, exclude?)`
  with tests (unhung preferred, fallback to all, exclude, empty library → null, textures never picked).
- Settings panel: default wall finish (texture select incl. "none", colour picker, tile size).
  Wall inspector: "Use default" vs custom finish (same three fields). Blueprint shows walls with a
  custom finish distinguishably (e.g. tinted or dashed outline).
- Delete-unused rules count texture references (settings + walls) as usage.
- Editor warnings: unchanged plus "texture referenced but missing" if applicable.
- **Non-loopback banner**: if `location.hostname` is not `localhost`, `127.0.0.1` or `[::1]`, show a
  persistent banner: saving only works from this computer via `https://localhost:<port>/editor.html`
  (render that as a link with the current port), and disable save/upload controls.
