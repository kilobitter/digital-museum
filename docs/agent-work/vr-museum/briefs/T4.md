## Done when
### A. Viewer streaming (`src/viewer/**`)
- **Paintings**: image + label textures are loaded only for works within `LOAD_RADIUS` (≈15 m,
  plan distance from head to work centre) and disposed (texture + material, GPU memory freed) beyond
  `UNLOAD_RADIUS` (≈20 m). Nearest-first queue, max ~4 concurrent loads, hard cap on resident painting
  textures (≈80; evict farthest). Until loaded, a work shows its frame with a neutral light-grey panel
  (not the "missing" placeholder). Missing files still get the missing placeholder + warning.
- **Draw calls**: frames of all works merged into one mesh (always visible); walls merged into one
  mesh per finish/material; only nearby image/label meshes exist in the scene. Target: a 500-work
  museum renders with < ~150 draw calls from any position (log `renderer.info.render.calls` in a
  debug overlay toggled by `?debug` in the URL, also showing resident textures and decoded audio).
- **Audio**: compressed bytes are fetched lazily (when a zone is within `AUDIO_LOAD` ≈ 10 m of its
  edge) and may be cached; **decoded** AudioBuffers exist only for zones within that range and are
  released beyond `AUDIO_UNLOAD` ≈ 15 m (stop + disconnect source, drop buffer). Gapless looping and
  smooth gains as today; a zone whose buffer arrives while the visitor is inside ramps in from 0.
- **Startup**: after museum.json + wall textures, load only what's needed around the spawn (with the
  progress UI), then show the start screen; everything else streams while walking.
- Keep these policies in pure, unit-tested functions (e.g. `planStreaming(head, items, resident,
  limits) -> { load: id[], unload: id[] }` with hysteresis, cap and nearest-first ordering).

### B. Editor bulk workflow (`src/editor/**`)
- **Paintings upload at max 1600 px longest side**, JPEG q≈0.82 (textures stay 1024).
- **Bulk upload queue**: dropping/picking hundreds of files uploads with concurrency ~3, shows
  "n / total" progress, collects per-file errors without stopping, and skips files whose original
  name + byte size match an existing library item (reported as "already in library").
- **Filename convention** on painting upload, pure function `parsePaintingFilename(name)` →
  `{ title, artist }`: strip extension; `_` → space; trim/collapse whitespace; split on the first
  ` - ` (also ` – ` / ` — `): left = artist, right = title; no separator → title = whole name,
  artist = "". Tests incl. multiple dashes, no separator, underscores, extra spaces, hyphenated names
  without spaces ("Jean-Luc - Sea.jpg").
- **Library at scale**: search (title, artist, filename), filter All / Hung / Unhung, counts
  ("312 paintings · 120 unhung"), small thumbnails rendered lazily so only visible items decode
  (virtualised or paged grid — implementer's choice; must stay responsive with 500 items).
- **Fill wall**: with a wall selected, "Fill face with random paintings" (choose side, painting
  width, gap, centerHeight) hangs as many unhung paintings as fit evenly along the face (falls back
  to random from all when none unhung, per the existing rule), as one undo step. Pure, tested
  function for the layout (count/positions for a given length, width, gap; zero when it doesn't fit;
  respects existing works on that face by only filling free spans — or, simpler, refuse if the face
  already has works; state which you chose).
