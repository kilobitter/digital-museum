## Goal and non-goals
A doorway is a gap between two wall pieces on one line. When the rooms on either side have different heights, the
gap above the door is closed today by a "ceiling step": a thin quad on the room boundary (usually the wall's centre
line), with the LOWER CEILING's finish. Seen from the tall room it looks wrong twice: wrong texture, and set back half
a wall thickness behind the wall faces.

Make it look like the wall continues over the door: same finish (texture, colour, gradient), flush with the wall's face
on the tall side, with a small underside so there is no gap when looking up.

Non-goals: no change to `museum.json` or the schema, no editor change, no real door lintel in rooms of equal height,
no change to the texture origin of walls (a seam on one side of the door for patterned textures is accepted), no change
to steps with no wall next to them.

## Done when
- A step piece with a parallel wall's drawn span touching either of its ends is drawn as a door header, in that wall's
  merged wall mesh, instead of as a ceiling quad.
- A step piece with no such wall is unchanged: same `stepQuad`, ceiling material, lower ceiling's finish.
- The header's face is exactly in the plane of the wall's face on the tall side, whichever way the wall was drawn
  (a to b either direction) and whichever side is tall, along plan x or plan y.
- The face's texture continues seamlessly from the chosen wall, and the gradient matches the wall's at the same height.
- No new draw call: headers join the existing wall mesh for that finish.
- Museums without room heights produce identical geometry to before.
- All tests and the build pass, and before/after renders exist (see Verification).

## Context and exact contracts

### Finding the wall: `uncoveredSteps` in src/viewer/surfaces.ts
Add an optional field to what it returns:
```ts
export interface UncoveredStep extends CeilingStep {
  /** The parallel wall whose drawn span touches this piece's end. Absent when none does. */
  wall?: Wall;
}
```
Leave the field out entirely (not `wall: undefined`) when no wall touches. Existing tests must keep passing unchanged.

The wall loop already computes each covering wall's drawn range `[lo, hi]` along the step's axis. Remember them. For each
free piece `[f0, f1]` choose, within 1e-6: first a wall with `hi ≈ f0` (the one before the piece along the axis), else a
wall with `lo ≈ f1`. So with two different finishes, the wall at the lower coordinate wins. `CeilingStep` and
`decomposeCeiling` do not change.

### Geometry: new exported function in src/viewer/wallGeometry.ts
```ts
export function doorHeaderGeometry(
  step: CeilingStep,
  wall: Wall,
  thickness: number,
  tileSize: number,
  /** the wall's drawn range in metres along the wall from `a`: pieces[0].from and pieces[last].to */
  drawn: { lo: number; hi: number },
): THREE.BufferGeometry
```
It returns world-space geometry with the attributes `position`, `normal`, `uv`, indexed, so it merges with wall boxes.
Make sure importing `CeilingStep` from surfaces.ts creates no circular import problem (a type-only import is fine).

Two quads. Let `d = wallDirection(wall)`, `n = step.normal` (points at the tall side), and let the plan coordinate
across the step be x for a step running along plan y, else y:

1. **Face.** Vertical, y from `step.bottom` to `step.top`, normal `(n.x, 0, n.y)`, spanning the step's a to b along the
   axis, in the plane `wall line + n * thickness / 2`. Use the wall's own across coordinate, NOT the step's: the wall
   may be up to thickness/2 off the step line. Winding must face `n` (see the check in `stepQuad`).
2. **Underside.** Horizontal at `y = step.bottom`, normal `(0, -1, 0)`, same extent along the axis, running across from
   the face plane back to the step line. Skip it when narrower than 1e-4 m. It ends exactly on the step line, because
   the low ceiling starts there at the same height: going past it would z-fight.

UVs must continue the wall box. From `wallGeometry` plus how scene.ts calls it, with `t` the distance along the wall from
`a` (`t = (p - wall.a) · d`):
- The wall's local +z face faces `perp = (-d.y, d.x)` in plan. There `u = (t - lo) / tileSize`.
- The opposite face has `u = (hi - t) / tileSize`.
- Use the +z formula when `n · perp > 0`, else the other one.
- On the face `v = y / tileSize` (world height, as on the wall). On the underside use the same `u` and
  `v = across distance from the face / tileSize`.
