## Goal
Collaborators each build a museum in their own folder (T9). The assembler imports those museums one by
one into theirs: each import is a **one-time copy** that keeps its original look, lands next to the
current museum already selected, and can then be dragged/rotated into place (T10) and joined with the
Door tool. A museum can be exported as a single .zip to send around.

## Done when

### A. Zip read/write, no dependencies (`src/editor/zip.ts` or `src/shared/zip.ts`, unit-tested)
- **Writer**: store-only (method 0) zip from `{ name, data: Blob }[]` → `Blob`. CRC-32, UTF-8 name flag
  (bit 11), DOS timestamps, local headers + central directory + EOCD. Build the output as a Blob of parts
  (reference the input Blobs, don't concatenate into one giant buffer); reading each input once for the
  CRC is fine. Refuse > 65535 entries or > 4 GB (no zip64).
- **Reader** over a `Blob` using `slice` (don't load the whole zip into memory): find EOCD, read the
  central directory, then each requested entry's local header for the data offset. Methods 0 and 8
  (deflate via `DecompressionStream('deflate-raw')`). Reject encrypted entries and zip64 with clear
  messages. Entry names are only ever used for lookup, never as write paths.
- **Museum layout inside a zip**: find `museum.json` at the shallowest depth, ignoring `__MACOSX/` and
  dot-files; media are looked up relative to that file's directory (so both "museum.json at the root"
  and "My museum/museum.json" — what an OS "Compress folder" produces — work). Limits: museum.json ≤ 5 MB,
  each media entry ≤ 50 MB (uncompressed, checked from the header and enforced while inflating).
- Tests: write → read round trip (names incl. non-ASCII, binary data, CRC check); a deflate entry
  (produce with `CompressionStream('deflate-raw')` in the test); nested-folder layout; `__MACOSX` ignored;
  encrypted flag rejected; truncated/garbage file → error, not a hang.

### B. Import source abstraction
- An import source = parsed guest museum + `readMedia(file: string): Promise<Blob | null>`.
- From a **.zip** (file input, accept `.zip`).
- From a **folder**: `showDirectoryPicker({ id: 'import', mode: 'read' })` when available (reuse the T9
  handle types), otherwise `<input type="file" webkitdirectory>`; same shallowest-`museum.json` rule.
  Reading only — never write to the guest folder.
- Guest JSON goes through `parseMuseum` (migrates older versions; a newer/invalid file → error listing
  the problems, nothing changes). Media `file` paths are already validated by `parseMuseum`.

### C. Pure merge (`src/editor/importMerge.ts`, heavily unit-tested)
`mergeMuseum(host, guest, media, opts)` where `media` maps each guest media id to either
`{ reuse: hostMediaId }` or `{ file: newFilePath }` (or is absent = file missing). Returns
`{ museum, selection: MultiSel, summary, warnings }`. Rules:
- **Fresh ids** for everything guest (walls, works, zones, areas, media), unique against host, via
  `newId`; all references remapped (work.mediaId/wallId, zone.mediaId, finishes' textureId, areas).
- **Media**: guest items appended to host media (except `reuse`). Default brings the whole guest library;
  `opts.onlyUsed` brings only media referenced by guest works, zones, finishes and areas. Guest **sky
  and its panorama** are not used (host sky stays); the panorama is imported only as a library item when
  bringing the whole library. Missing files: drop that media item, drop works/zones that use it, drop a
  missing texture from a finish (keep the colour); each → warning.
- **Dedupe**: done by the caller before merge — a guest media item whose `file` path equals a host media
  item's `file` and same `kind` → `{ reuse }` (covers museums started from a common copy). No content hashing.
- **Keep their look**:
  - Guest walls with no `finish` get the guest default `wallFinish` explicitly, **only when** it differs
    from the host default (compare after texture remap; deep equality).
  - If the guest default floor finish differs from the host's, or the guest default ceiling finish
    differs, or guest `settings.ceiling === false` (while host has ceilings): add one **base area** named
    `"<guest name> (base)"` over the bounding box of the guest walls, with `floor` = guest floor finish
    (when it differs), and `ceiling` = guest ceiling finish (when it differs) **or** `openSky: true`
    (when the guest had ceilings off). It goes before the guest's own areas, which follow in their order,
    all after the host's areas. No walls → no base area.
  - Guest had ceilings off: also strip `ceiling` from the guest's own areas (they were invisible there);
    an area left with neither floor nor openSky is dropped.
  - If the resulting area would have nothing (no floor, no ceiling, no openSky), don't add it.
- **Kept from host**: name, all settings (wall height/thickness, grid, finishes, sky, spawn, ceiling).
  Warnings: guest wall height differs ("their walls were X m, yours are Y m"); each guest work whose top
  (`centerHeight + imageHeight/2`) exceeds host wall height; guest wall thickness differs (info).
- **Placement**: offset = (host bbox maxX + 2 m − guest bbox minX, host bbox minY − guest bbox minY),
  snapped to host grid. Bboxes over walls, zones, areas (not spawn). Empty host → offset 0. Empty
  guest plan → only media are added.
- **Selection** returned = all imported walls, zones, areas (works ride along with walls) — for the T10
  group tools.
- Tests: ids unique and `parseMuseum` passes; references remapped; reuse dedupe; onlyUsed; missing
  file drops; finish baking only when different; base area cases (floor differs; ceiling differs;
  ceilings off → openSky + stripped guest ceilings; nothing differs → no base area); placement offset
  and grid snap; empty host; empty guest; warnings for wall height / tall works; host sky and spawn
  untouched; importing the same guest twice gives two independent copies.

  export anyway, list them in a notice.
