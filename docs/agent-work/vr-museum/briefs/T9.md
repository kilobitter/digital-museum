## Goal
Non-technical collaborators open `https://<pages-site>/editor.html` in Chrome or Edge, pick a folder on
their own computer, and build their own museum there — no install. The folder has exactly the same
layout as `public/museum/` (`museum.json` + `media/<id>.<ext>`), so it can later be imported (T11) or
copied into `public/museum/`. They can preview their museum in the desktop viewer on the same site.
The existing local dev workflow (dev API on localhost) keeps working unchanged.

## Done when

### A. Storage abstraction (`src/editor/`)
- One interface the editor uses for all persistence and media URLs, e.g.
  ```ts
  interface MuseumStore {
    kind: 'dev' | 'folder';
    label: string;                          // shown in the top bar, e.g. "Dev server" / folder name
    load(): Promise<LoadResult>;            // existing LoadResult shape (ok | missing | invalid)
    save(m: Museum): Promise<SaveOutcome>;  // validates with parseMuseum first, as today
    upload(name: string, data: Blob): Promise<string>;   // returns "media/<id>.<ext>"
    deleteMedia(file: string): Promise<void>;            // missing file is not an error
    mediaUrl(file: string): string | undefined;          // synchronous; for <img>, <audio>, SVG patterns
  }
  ```
  Exact shape is yours; it must cover these responsibilities. The dev store wraps today's `api.ts`
  behaviour (mediaUrl = `./museum/<file>`).
- Replace every hard-coded `./museum/${file}` in the editor (Library, Inspector, Canvas patterns,
  audio preview) with the store's URL. App's `local`/"can save" logic becomes "store is writable".
- Store selection on startup: dev store iff `import.meta.env.DEV && isLoopbackHost(location.hostname)`
  and the URL has no `?folder` param; otherwise the folder flow. The dev-store code path must be
  dead-code-eliminated from the production bundle (no `/api/` strings in `dist/assets/*.js`).
  The old "editor is loopback only / read-only" banner goes away (non-loopback now gets the folder flow).

### B. Folder store (File System Access API)
- Pure-ish core written against a small injected directory interface (getFile/getDir/write/remove/list),
  so it is unit-tested in vitest with an in-memory fake; a thin adapter maps it to real
  `FileSystemDirectoryHandle`. Declare the missing DOM types (`showDirectoryPicker`,
  `queryPermission`/`requestPermission`) locally — no new dependencies.
- Load: `museum.json` absent → `missing` (start from `defaultMuseum()`); present → parse with
  `parseMuseum` (migrates). On load, list `media/` and build the file → object-URL map for files whose
  names match the shared media-file pattern (ignore anything else; never resolve paths with `/` or `..`).
- Upload: same extension allowlist and 50 MB cap as the dev API; id = 10 chars `[a-z0-9]` from
  `crypto.getRandomValues`; retry on collision; writes `media/<id>.<ext>`; adds to the URL map.
- Save: write `museum.json` (pretty JSON + trailing newline, same as dev API) via `createWritable`.
  **External-change guard**: remember `lastModified` of `museum.json` after each load/save; before
  writing, re-read it — if it changed (another tab, a sync client, the user copying files), do not
  write; surface an error state with two choices: "Reload from folder" (discards in-memory changes
  after confirm) or "Overwrite". Autosave pauses while in that state. Test this with the fake.
- Delete media: removeEntry; NotFound is fine; revoke its object URL.
- Move the media-file regex/allowlist into `src/shared/` (one source of truth) and import it from
  `validate.ts`, the folder store and `src/devserver/museumApi.ts` (that one-line import change is the
  only edit allowed in museumApi.ts; its tests must still pass).

### C. Start screen (folder flow)
- Shown when no folder is open. Plain-language copy for non-technical users:
  - **Open museum folder** — "Pick an empty folder to start a new museum, or a folder that already has one."
    `showDirectoryPicker({ id: 'museum', mode: 'readwrite' })`.
  - If the picked folder is non-empty and has no `museum.json`: confirm ("This folder already contains
    other files. Create a museum here anyway?") before writing anything.
  - **Reopen "<name>"** when a previous handle is stored (IndexedDB, raw API, no dependency): one click
    → `requestPermission` (user gesture) → load. If the handle is gone/denied, say so and fall back to Open.
  - Unsupported browser (`showDirectoryPicker` missing): explain it needs Chrome or Edge on a computer;
    mention Brave needs `brave://flags/#file-system-access-api` enabled; Safari/Firefox are not supported.
- Top bar shows the folder name and a "Switch folder" action (flushes a pending save first).
- Only the folder's own files are touched: `museum.json`, `museum.json` temp writes from
  `createWritable`, and `media/*`. Never anything else.

### D. Preview from a folder (`src/viewer/main.ts` + small helper)
- Editor's Preview button: dev store → `./index.html` (as today); folder store → `./index.html?source=folder`.
- Viewer with `?source=folder`: read the stored handle from the same IndexedDB key; if permission is
  not `granted`, show a button ("Allow access to <name>") on the start overlay that calls
  `requestPermission`; then read `museum.json` and build a file → object-URL map for media and pass it
  as the existing `urlFor`. Without the param, the viewer is unchanged (fetches `./museum/`). Errors use
  the existing error UI. (No XR-specific work — Quest browsers lack this API; desktop preview only.)
- Share the IndexedDB handle helper between editor and viewer (e.g. `src/shared/folderHandle.ts`) —
  keep it free of React and three.js.
