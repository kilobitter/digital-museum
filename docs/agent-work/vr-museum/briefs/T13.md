## Fixed contracts (do not deviate)

### Sealed format v1
- `public/sealed/manifest.json`:
  `{ "format": "vr-museum-sealed", "version": 1, "kdf": { "name": "PBKDF2", "hash": "SHA-256", "iterations": 600000, "salt": "<base64, 16 random bytes>" }, "cipher": "AES-GCM" }`
- Key: PBKDF2-SHA256(password UTF-8, salt, iterations) → AES-GCM 256-bit key.
- Each sealed file = ASCII `VMS1` (4 bytes) ‖ 12-byte random IV ‖ AES-GCM ciphertext incl. 16-byte tag.
  **AAD = UTF-8 of the logical path**: `museum.json` or `media/<name>.<ext>` (the exact `file` value
  from museum.json). So swapping/renaming sealed files makes decryption fail.
- Paths: `public/sealed/museum.json.enc`, `public/sealed/media/<name>.<ext>.enc`.
- Readers must reject: wrong magic, file shorter than 4+12+16, unknown format/version/kdf/hash/cipher,
  `iterations` outside [100000, 10000000], salt not 16 bytes. A failed GCM open is one error kind
  ("wrong password or damaged file"); never return partial plaintext.

### `scripts/seal.mjs` (plain Node ESM, no deps, `globalThis.crypto.subtle`), npm script `"seal": "node scripts/seal.mjs"`
- `node scripts/seal.mjs [--src <dir>] [--out <dir>] [--rekey]`, defaults `public/museum` → `public/sealed`.
- Password from env `MUSEUM_PASSWORD`, else a hidden TTY prompt; with no TTY and no env → exit 2 with a
  clear message. New manifest or `--rekey`: ask twice (env counts as confirmed), require ≥ 12 chars.
- Existing manifest without `--rekey`: derive key, **verify by opening the existing `museum.json.enc`**;
  on failure print "Wrong password (use --rekey to set a new one)", exit 1, **write nothing**.
  (If the manifest exists but `museum.json.enc` does not, treat as verification impossible → exit 1 with
  a message suggesting `--rekey`.)
- `--rekey`: new random salt, re-encrypt everything.
- Seals `museum.json` (must parse as JSON; else exit 1) and every `media[].file` it lists that exists in
  `<src>/media`. Missing listed files: warn, continue. Unlisted files in `<src>/media` are not sealed.
  Validate each `file` with the same rule as `MEDIA_FILE_RE` in `src/shared/mediaFiles.ts` (copy the
  regex; skip + warn on mismatch — never let a path escape `<out>`).
- **Idempotent**: if an existing `.enc` opens (with the current key) to byte-identical plaintext, leave it
  untouched (no git churn). Otherwise write a fresh one (new IV). Writes are atomic (tmp + rename).
  Delete `.enc` files in `<out>/media` that are no longer listed. Never touch anything else in `<out>`.
- Prints a summary: sealed / unchanged / removed / missing counts; exit 0.

### Viewer
- New `src/viewer/sealed.ts`: WebCrypto implementation of the format, usable in browsers and in vitest
  (Node): parse/validate manifest, derive key (non-extractable), open a sealed `ArrayBuffer` for a path,
  and a seal function (used by tests). Typed error for wrong-key/damaged vs malformed.
- New media-opener hook so `scene.ts`, `streamer.ts`, `sky.ts` stay untouched: e.g. `src/viewer/mediaOpener.ts`
  exporting `openMedia(url): Promise<{ url: string; release(): void }>` (default: same url, no-op release)
  and `setMediaOpener(fn)`. Call it in `textures.ts` (`loadTexture`/image load) and in `audio.ts`
  (before `fetch`), releasing as soon as the image has loaded / the bytes are read, also on error.
  In sealed mode the opener fetches the `.enc`, decrypts with the AAD of the logical path, and returns a
  `blob:` URL (with a sensible MIME type from the extension), revoked on release.
- `main.ts` mode selection:
  1. `?source=folder` → unchanged folder preview.
  2. `import.meta.env.DEV` and no `?sealed` param → unchanged plaintext `./museum/`.
  3. Otherwise sealed: fetch `./sealed/manifest.json` (404/invalid → clear error screen, e.g. "This museum
     has not been published yet" / details). Password screen (`ui.ts`: input `type=password`,
     `autocomplete=current-password`, Enter submits, "Remember on this device" checkbox, error line).
     Show "Unlocking…" while deriving. Wrong password → back to the screen with "Wrong password".
     `urlFor(file)` = `./sealed/<file>.enc`; install the sealed opener; then continue exactly as today.
- Remember: store the non-extractable `CryptoKey` in IndexedDB (own small DB/store, keyed by the manifest
  salt) only when ticked. On load try the stored key first; if it fails to open `museum.json.enc`, delete
  it and show the password screen. The start screen offers "Forget password on this device" when a stored
  key was used (deletes it and reloads). IndexedDB unavailable → just don't remember (no crash).
- Styles for the input/checkbox go in `index.html` next to the existing `#panel` rules, same look.
