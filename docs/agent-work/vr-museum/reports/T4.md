## Changes
Viewer (src/viewer)
- streaming.ts (+test): pure policy. `planByDistance(entries, resident, loading, limits)` and `planStreaming(head, items, resident, loading, limits) -> {load, unload}`: load only items within loadRadius, keep until unloadRadius (hysteresis), hard cap on resident+loading (nearest win, farthest evicted), nearest-first loads limited by free concurrency slots, in-flight loads that drift out are cancelled. Limits: PAINTING_LIMITS 15/20 m, cap 70, 4 concurrent; AUDIO_LIMITS 10/15 m (distance to zone edge), cap 8, 2 concurrent.
- textures.ts (new): loadTexture/placeholderTexture/labelTexture moved out of scene.ts; painting texture cap 1600 px (was 2048).
- scene.ts: static geometry only. Walls merged into one mesh per material (finish key), all frames in one mesh, all neutral light-grey (#d9d9d9) panels in one mesh (always visible; shown until the image arrives). Returns `slots` (per-work placement) for the streamer. Uses three/examples/jsm/utils/BufferGeometryUtils (already part of three).
- streamer.ts (new): PaintingStreamer. Creates image+label meshes only for resident works; on unload removes them and disposes texture, label texture, materials, geometries. Request tokens discard stale/cancelled loads. Missing file -> shared "missing" placeholder + warning (not the grey panel). `update(head)` replans after 0.5 m of movement and after each finished load; `prime(head, onProgress)` loads the spawn neighbourhood before the start screen.
- audio.ts: rewritten as streamed. Compressed bytes are fetched lazily when a zone is within 10 m of its edge, decoded buffers are shared per file with ref-counting, and on release (beyond 15 m or over the cap of 8) the source is stopped and disconnected, buffer dropped. Compressed bytes are NOT cached by the app (HTTP cache only), to keep memory bounded. New voices start at gain 0 and ramp via setTargetAtTime, so a zone arriving while the visitor is inside fades in. Loop is still a looping AudioBufferSourceNode. Failed zones are skipped permanently with a warning.
- main.ts: startup = museum.json, wall textures, then paintings and audio around the spawn with "Loading paintings n / t" progress, then the start screen; everything else streams in the render loop. Start-screen warnings and the toast include streamer/audio warnings collected so far.
- debug.ts (new) + main.ts: `?debug` overlay with draw calls, triangles, GPU textures, geometries, resident paintings, decoded audio, fps.

## Remaining risks / decisions for Opus
1. Duplicate detection by "original name + byte size": the v2 contract has no field for the original size and I may not change it. I record original sizes per browser in localStorage (key museum-editor.uploadSizes) and match on name plus size when a size is known; items with no recorded size (everything uploaded before this change, or from another browser) match on name alone. Decide whether to accept this or add an optional size field to MediaItem later.
2. Fill wall: I chose the simple option, refuse when that face already has works (stated in the UI and README). End gaps equal the inter-painting gap, and tall portraits are not checked against wall height.
3. Caps differ slightly from the brief's "~80": painting cap is 70 so the worst-case draw-call count stays under 150; audio cap 8 (decoded 2-minute stereo loops are ~20-40 MB each). Both are constants in src/viewer/streaming.ts.
4. The same painting hung N times loads N textures (no sharing by media id), fine for the intended one-painting-per-work use.
5. Editor library thumbnails are the 1600 px files scaled by CSS (no separate thumbnail files); only the ~10 mounted cards decode, but they are not tiny. Generating thumbnails would need new media files, which is out of scope here.
6. Undo of a bulk upload removes the media entries but leaves the uploaded files on disk (same as before for single uploads).
7. The `?debug` overlay is a DOM element, so it is not visible inside an immersive VR session.
